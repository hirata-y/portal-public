# ADR 002 — B1日本語検索の限定是正と技術採用提案

状態：A実証済みの提案。Ownerの正式採用・B1受入・G4判断を代行しない。対象は合成ローカルPoC。

Astro 7.3.8の静的生成は成功する。Pagefind 1.5.2 Extended単独では「奥多摩」が期待2詳細に対し0詳細となるため、標準クライアントの無条件採用は提案しない。公開索引から分割語を抽出する小さな照会補助を追加し、既存Vanilla検索・構造化フィルタを保持したまま、別画面 `/search/` で実Pagefindを利用可能にした。

## 原因と実装

上流v1.5.2、commit bf17396721be637cc67c8ed7ead1dc7b8ac43d96を読取り確認。CLIはCharabia 0.9.3の日本語分割、照会はIntl.Segmenter。実fragmentの「架空／奥多／摩／A」とブラウザの「奥多摩」が一致しない。第一案の空白補助だけではクライアントが再分割するため失敗した。

`create_ja_lexicon.mjs` が公開fragment13件の実分割219語と元fragment SHAを抽出する。`pagefind-ja.js` が語を一般的に分割し、最大32候補・入力200文字に制限し、照会候補を引用付きフレーズとして渡す。専用Worker内だけIntl.Segmenterを無効にして、Pagefind自身の非Intlフォールバックで分割済み空白を保持する。ネイティブJS/WASMが索引検索・照合・fragment取得を行い、その結果を重複排除して返す。ブラウザ本体のIntl、vendor配布26ファイル、元P3-A 16ファイルを変更しない。「奥多摩」固定のID表・部分一致検索の代用品ではない。

この方式はPagefindの不具合そのものの修正ではない。標準API単独の対照試験は今回も詳細0。補助を含む統合についてのみAのPASSを主張する。Pagefind生成fragmentの内部形式と非Intlフォールバックに依存するため、バージョン更新時は専用回帰が必要。一般的な日本語形態素検索・同義語・任意部分一致の保証はない。複数の候補でのスコアは単一検索の全体順位ではない。今回UIはレコード詳細だけを表示し、入力語順の一致を案内する。高度なfilter/sort/merge/ranking APIの互換レイヤーではない。

## 採用提案と残条件

B1のPoC成果としてAstro静的生成と補助付きPagefindを評価対象に残す。ホームのVanilla構造化検索を保持し、Pagefindによる全面置換は行わない。8件の現段階では保守負担・配布増が検索利益を上回り得るため、MVP採用は別途Owner判断とする。将来件数・全文検索ニーズを根拠に採否を決め、無根拠な増強を始めない。

`npm audit --json` は2026-10-15にexit0・既知脆弱性0。lock267依存のlicense metadataに欠落なし。MIT/Apache/BSD等に加えsharp/libvips系のLGPL、MPL等があり、ビルド用・任意platform依存を含む。直接依存の配布licenseを `docs/third-party/` に保存。これは法的承認やバイナリ／辞書を含む全権利証明ではない。本番配布形態・NOTICE・ライセンス適合の確認は採用時に残す。

初回Freeze後の別セッションF限定レビューに回す。P3-Aの過去F BLOCKEDは変更しない。B1 Fが成功してもCT01/02/06、DG012、52 N/A、全WCAG/AT等の別停止点とG4 STOPを保持する。
